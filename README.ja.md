# VSFilterMod — クロスプラットフォーム版

[![CI](https://github.com/cgyihai/VSFilterMod/actions/workflows/ci.yml/badge.svg)](https://github.com/cgyihai/VSFilterMod/actions/workflows/ci.yml)
[![License: GPL v2+](https://img.shields.io/badge/license-GPL--2.0--or--later-blue.svg)](LICENSE)
![Platforms](https://img.shields.io/badge/platforms-Windows%20%7C%20Linux%20%7C%20macOS-lightgrey.svg)

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語** | [한국어](README.ko.md)

VSFilterMod 字幕レンダラーを **Windows、Linux、macOS** に移植したものです。
ビルド成果物は単一のライブラリで、Aegisub 用の **CSRI** プラグイン、
**AviSynth+** プラグイン（`TextSubMod` / `MaskSubMod`）、**VapourSynth**
プラグイン（`vsfm.TextSubMod`）として機能します。さらにコマンドラインツール
`vsfmrender` も含まれ、字幕を Blu-ray 制作向けの **BDN+XML** に直接
レンダリングできます。

ASS パーサーとラスタライザーは VSFilterMod オリジナルのコードなので、すべての
拡張タグがそのまま使えます：`\pngimg` 画像背景、`\glow` グロー、グラデーション、
可動ベクター clip、`\rnd` ジッター、distort、`\frs` 文字回転、Z 座標、
縦方向スペーシングなど。

## 特徴

- **3 プラットフォームで同一のレンダラー。** グリフはすべて FreeType が供給するため、
  同じ字幕が Windows、Linux、macOS で同じ結果になります。
- **オリジナルの挙動を再現し、実測で検証済み。** VSFilterMod の組版が GDI に依存する
  部分——セル高によるフォントサイズ決定、合成ボールド・イタリック、`\frs`、`@` 縦書き
  フォント、グリフフォールバック——は、エンジンが GDI の実際の動作を再現します。
  これらの規則は GDI を直接計測して得られたもので、オリジナルとピクセル単位で
  比較済みです。
- **Aegisub プラグイン**（CSRI）。リアルタイムプレビュー用。
- **AviSynth+ プラグイン**。`TextSubMod` / `MaskSubMod` の引数はオリジナルと
  同一で、既存スクリプトや avs2bdnxml がそのまま使えます。
- **VapourSynth プラグイン**（API 4）。`vsfm.TextSubMod` の引数はオリジナルと同一：
  8 ビット出力はオリジナルと一致し、9〜16 ビットの YUV と RGB はフル精度で混合、
  4:2:2 とグレースケールもサポート。
- **BDN+XML 出力**：`vsfmrender` の結果は、avs2bdnxml が本プラグインの
  `MaskSubMod` を呼び出した結果とバイト単位で一致します。
- **埋め込みフォント**（`[Fonts]` アタッチメント）が CSRI 経由でも使えます。
- **出力はマシンに依存しません**。DPI とコードページは固定され、環境設定を
  読みません。

## ダウンロード

プッシュのたびに GitHub Actions が全プラットフォームで自動ビルドします。
バージョンタグ付きの正式リリースは
[Releases](https://github.com/cgyihai/VSFilterMod/releases) ページに公開され、
任意のコミットのビルド成果物は [Actions](https://github.com/cgyihai/VSFilterMod/actions)
ページの対応する実行の *Artifacts* からダウンロードできます。

| プラットフォーム | パッケージ | 内容 |
| --- | --- | --- |
| Windows x86_64 | `vsfiltermod-windows-x86_64-msvc` | `vsfiltermod.dll`、`vsfmrender.exe` |
| Windows x86（32 ビット） | `vsfiltermod-windows-x86-msvc` | `vsfiltermod.dll`、`vsfmrender.exe`。32 ビットの Aegisub、AviSynth+、avs2bdnxml 用 |
| Windows ARM64 | `vsfiltermod-windows-arm64-msvc` | `vsfiltermod.dll`、`vsfmrender.exe` |
| Linux x86_64 | `vsfiltermod-linux-x86_64` | `vsfiltermod.so`、`vsfmrender` |
| Linux aarch64 | `vsfiltermod-linux-aarch64` | `vsfiltermod.so`、`vsfmrender` |
| macOS ユニバーサル | `vsfiltermod-macos-universal` | `vsfiltermod.dylib`、`vsfmrender`。Apple Silicon と Intel の二合一 |
| macOS Apple Silicon | `vsfiltermod-macos-arm64` | `vsfiltermod.dylib`、`vsfmrender` |
| macOS Intel | `vsfiltermod-macos-x86_64` | `vsfiltermod.dylib`、`vsfmrender` |

すべてのビルドは同一固定バージョンの FreeType と libpng を静的リンクしているため、
レンダリング結果は完全に同一です。Windows 版は追加 DLL 不要です。macOS 版は
システム以外のライブラリに依存せず、macOS 11 以降（Apple Silicon）および
10.15 以降（Intel）に対応します。Linux 版は fontconfig と zlib（すべてのデスクトップ
ディストリビューションに存在）のみに依存し、glibc 2.35 以降（Ubuntu 22.04、
Debian 12、Fedora 36 以降）に対応します。各リリースには `SHA256SUMS` 検証ファイルが
付属します。

## 使い方

### Aegisub

**Windows：** `vsfiltermod.dll` を `aegisub.exe` の隣の `csri` フォルダに入れ、
Aegisub を再起動して *オプション → 詳細 → 動画 → 字幕レンダラー* で
**CSRI/vsfiltermod_textsub** を選択します。

**Linux / macOS：** 公式 Aegisub はこれらのプラットフォームで CSRI プラグインを
読み込みません。先に Aegisub へ
[`docs/aegisub-csri-posix.patch`](docs/aegisub-csri-posix.patch)
を適用して再ビルドし、次を実行します：

```bash
mkdir -p ~/.csri
cp vsfiltermod.so ~/.csri/          # macOS では vsfiltermod.dylib
chmod +x ~/.csri/vsfiltermod.so     # ローダーは実行権限のないファイルをスキップ
```

詳細は [BUILD.ja.md](BUILD.ja.md#aegisub-へのインストール) を参照。

### AviSynth+ と avs2bdnxml

同じライブラリが AviSynth+ プラグインにもなります：

```avs
LoadPlugin("vsfiltermod.dll")
MaskSubMod("subtitle.ass", 1920, 1080, 23.976, 3000)   # RGBA 出力。avs2bdnxml 用
# または動画にオーバーレイ：
# TextSubMod("subtitle.ass")
```

AviSynth+ 経由でスクリプトを読み込む avs2bdnxml はすべて使用可能です。32 ビットの
avs2bdnxml または AviSynth+ には 32 ビット（`windows-x86`）版を、それ以外には
64 ビット版を使ってください。

### VapourSynth

同じライブラリが VapourSynth プラグイン（API 4、VapourSynth R55 以降）にもなり、
名前空間と引数はオリジナルと同一です：

```python
import vapoursynth as vs
core = vs.core
core.std.LoadPlugin("vsfiltermod.dll")      # プラグインディレクトリに配置済みなら省略可
clip = core.vsfm.TextSubMod(clip, "subtitle.ass")
# TextSubMod(clip, file, charset=1, fps=..., vfr="timecodes.txt")
```

4:2:0 または 4:2:2 の YUV、グレースケール、RGB を、サンプル当たり 8〜16 ビットで
サポートします。YUV420P8 と RGB24 の出力はオリジナルフィルタと完全に同一です。
オリジナルは 10 ビットと 16 ビットのクリップを 2 つの 8 ビット半分に分割して描画して
いましたが、こちらは各ビット深度を自身の精度で混合するため、`accurate=` はまだ
渡せますがもはや不要です。4:4:4 は先に RGB へ変換してください。

### vsfmrender

AviSynth を介さず、字幕を直接 BDN+XML にレンダリングします：

```bash
vsfmrender --size 1920x1080 --fps 23.976 input.ass output.xml
```

| オプション | 意味 |
| --- | --- |
| `-s, --size WxH` | フレームサイズ（デフォルト `1920x1080`） |
| `-f, --fps RATE` | `23.976`、`24`、`25`、`29.97`、`50`、`59.94`、または正確な分数 |
| `-l, --lang CODE` | ISO 639-2 言語コード（デフォルト `und`） |
| `-t, --title TEXT` | インデックスに記録するタイトル |
| `--first N` / `--last N` | エクスポートするフレーム範囲 |
| `--no-crop` | フルフレーム画像を出力（avs2bdnxml の `-a0` 相当） |
| `--fontdir DIR` | `DIR`（サブディレクトリ含む）のフォントをインストール済みフォントより優先して使用。繰り返し指定可 |
| `--font-report` | スクリプトが使う各フォントが実際にどのフォントファイルに解決されたか一覧表示 |
| `--strict-fonts` | フォントが 1 つでも置き換えられたら終了コード 3 で失敗 |
| `-q, --quiet` | 進捗を表示しない |

### エディター統合（タグメタデータ）

字幕エディターは、エディターの同期リリースなしに、2 つの等価なチャンネルで
このレンダラーの拡張タグ（`\glow`、`\imgscale`、`\matte` など）を検出できます：

- **ファイル**：ビルドのたびにレンダラー出力ディレクトリへ
  `vsfiltermod-tags.json` が生成されます（Windows では `VSFilterMod.dll` の隣）。
  ファイルは UTF-8 JSON ドキュメント
  `{ "version": 1, "renderer": ..., "tags": [...] }` で、各タグに `name`、
  `signature`、1 行の `help` が含まれます。エディターは通常のファイル IO で
  タグ配列をオートコンプリートに統合できます。
- **プラグインエクスポート**：ライブラリは
  `const char *csri_typesub_tags_json(void)` もエクスポートしており、
  同一ドキュメントを返します。プラグインを読み込んだ後に
  `GetProcAddress`/`dlsym` でシンボルを検索したいエディター向けです。

2 つのチャンネルの内容はバイト単位で一致（テストスイートで検証済み）なので、
エディターは便利な方を**一度だけ**実装すればよいのです。その後、新しい
レンダラービルドでタグが追加・更新されても、新しいバイナリ（または新しい
JSON ファイル）に置き換えるだけで、エディター側の更新は一切不要です。
未知のメタデータや欠落したメタデータは単純に無視してください：ファイルと
エクスポートシンボルはどちらもオプションで、`version` フィールドが将来の
フォーマット拡張に備えています。

### エフェクトパッケージ（\glowc、\glowa、\iglow、\mblur、\bevel、\clipf）

\glow のオプション仲間と 4 つの新エフェクト。すべて \t アニメーション対応、
値 0 で無効：

```ass
{\glowc&HBBGGRR&}    グロー色オーバーライド（デフォルトはメインカラー追従）
{\glowa&HAA&}        グロー不透明度オーバーライド（ASS 慣例：00 不透明、FF 透明）
{\iglow8}            内側グロー半径 8：光がグリフ端から内側へにじむ
{\iglow(8,1.5)}      強度付き。\iglowc / \iglowa で色/透明度を上書き（デフォルト白）
{\mblur45,10}        方向性モーションブラー：45 度方向に 10 出力ピクセル残像
{\bevel2}            滑らかなベベル/エンボス、サイズ 2
{\clipf15}           フェザークリップ半径 15：矩形・ベクター・反転クリップすべて
```

\iglow は本文の後に合成され、グリフ内部に厳密に制限されてはみ出しません。
\mblur は完成ビットマップを決定論的な整数サンプリングで処理します。
\clipf はその行のクリップを柔らかくします：矩形クリップはラスタ領域を外側へ
拡げ、名目矩形の外でフェードアウトします。ベクタークリップマスクは解析完了後に
一度だけブラーされ、すべての描画とグローパスが自動的にソフトエッジを継承します。
回帰テスト tests/fxpackage.py が全エフェクトをカバーします。

### グラデーション（\1vc、\vgrad、\rgrad）

従来の \1vc/\2vc/\3vc/\4vc タグは各ワード上で 4 隅の色を双線形補間します。
2 つの修飾タグで補間方法を変えられます。どちらも vc の最初の 2 色を始点・終点色とし、
\t アニメーションに対応し、互いに排他的です——後に書いた方が有効：

```ass
{\1vc(&H0000FF&,&HFF0000&,&H0000FF&,&HFF0000&)\vgrad45}45 度方向の線形グラデーション
{\1vc(&H0000FF&,&HFF0000&,&H0000FF&,&HFF0000&)\rgrad1}中央の放射グラデーション
{\rgrad(1.5,0.5,0.2)}半径 1.5 倍、中心は幅 50% / 高さ 20% の位置
{\rgrad0}双線形 4 隅混合へ戻る
```

\vgrad(angle) はグリフバウンディングボックスを指定角度方向（0 は左から右、
90 は上から下）へ投影します。\rgrad(scale[,cx,cy]) は中心点から外側へ
放射します：最初の vc 色が中心に位置し、線形距離で 2 番目の色へ遷移します。
半径の上限は中心からバウンディングボックス最遠隅までの距離の scale 倍です。
cx/cy は画面方向の UV 比率で中心を決め、デフォルトはボックス中心です。
回帰テスト tests/vgrad.py と tests/rgrad.py がこれらの意味論を固定しています。

### 円弧テキスト

`\arc(radius[,angle])` は行ベースラインを、行アンカー（配置行では `\pos` 点）を
中心とした `radius` 出力ピクセルの円周に巻き付けます。angle が 0 のとき行の中心が
円の頂点に来て、文字は時計回りに並びます：短いテキストは虹のアーチ型に、長い
テキストは円盤状に一周できます。半径が正なら文字は円の外側、負なら内側に来ます。
`\arc120` は省略形で、`\t` アニメーションに対応し、`\arc0` で無効化します。
組版は 1 文字ずつ分割されるため、ラテン連字・カーニングは無効になります
（CJK は影響なし）。`\fsp` 字間は円弧に沿って通常どおり適用されます。

### `\wave(amp,freq[,phase])` — 正弦波テキスト

行ベースラインを正弦波に巻き付けます：各グリフが進行位置に応じて `amp*sin`
の垂直変位を受け、波の接線方向へ回転します（変位後のベースライン中点がピボット）。
`amp`/`freq` は出力ピクセル（`freq` は完全な波長）、`phase` は度数です。
`\wave0` で無効化。`\t` は 3 つのパラメータすべてをアニメーション可能です
（`phase` をアニメーションすると波が流れます）。`\arc` と同様に 1 文字ずつ分割
（ラテン連字は無効、CJK は影響なし）で、`\arc` およびすべてのビットマップ
エフェクトと組み合わせられます。

### トラックマット（\matte、\imatte）

トラックマットは、あるイベントのシルエットでその上のレイヤーのイベントを
マスクする After Effects 方式です。マットイベント自身は非表示です。
対象レイヤーのイベントは完全にレンダリングされます——本文、アウトライン、
シャドウ、グローとすべての後処理エフェクト——ただしマットが不透明な部分のみ
表示されます：

```ass
Dialogue: 0,...,{\pos(320,180)}TEXT        表示されるベースレイヤー
Dialogue: 1,...,{\pos(320,180)\matte}TEXT  非表示のマットコピー。レイヤー 2 をマスク
Dialogue: 2,...,{\pos(320,180)\1vc(...)\rgrad1}WWWWW  グラデーションは TEXT 内部のみ表示
```

- `\matte` / `\matte1` / `\matte(1)` は layer+1 層をマスク。`\matte2` は
  layer+2 層（疎なレイヤー番号向け）。`\matte0` で無効。
- `\imatte` は反転：マットの外側にエフェクトが表示されます。
- 同じレイヤーの複数のマットイベントは和集合として 1 つのマスクになります。
- マスクはマットのレンダリング済みシルエットから取られます（シャドウ、
  アウトライン、本文を含む）。マット上のブラーやグローはマスクエッジを
  それに応じて柔らかくします。
- マットと被マットイベントはそれぞれフレームごとにアニメーションし、
  \move/\t の両方が同期を保ちます。

回帰テスト tests/matte.py は包含、反転、レイヤーオフセット、非表示、
文法バリアントをカバーします。

### `\extrude(depth[,angle])` — 立体押し出し

押し出し方向に沿って 1px ステップでシャドウ色のコピーを描画し
（デフォルトは画面座標で 45 度）、実体の側面を形成します。色と不透明度は
シャドウスタイル（`\4c`/`\4a`）から取られ、シャドウ深度がゼロでも独立して
使えます。`\extrude0` で無効。`\t` は depth と angle をアニメーションします。

### `\echo(count,dx,dy[,falloff])` — 残像トレイル

完全にレンダリングされたイベントを、ステップ状の整数オフセットでコピーごとに
合成し、alpha を層ごとに減衰させます（デフォルト 0.5）。メインコピーは最後に
合成されます。グロー、グラデーション、ブラーなどすべてのエフェクトが正確に
捕捉されます。count の上限は 32。`\echo0` で無効。`\t` は全パラメータを
アニメーションします。イベントレベル：行には最後のオーバーライドブロックの
パラメータが適用されます。

### `\persp(dist)` — 真の透視カメラ距離

`\frx`/`\fry` 3D 回転のカメラ距離（出力ピクセル）。小さい距離は強い
遠近短縮を生み（近端が拡大、遠端が圧縮）、大きい距離は従来の ASS の
正射影に近づきます。`\persp0` で従来の投影に戻ります。`\t` アニメーション対応。

### 行連続イメージフィルと `\imgscale(sx[,sy])`

`\1img`–`\4img` の PNG フィルは、行レベルのスクリーン座標でサンプリングする
ようになり、各ワードのオーバーレイバウンディングボックスでテクスチャが
再開されなくなりました。タイル画像は行内のすべてのワードをまたいで連続的に
流れ、矩形クリップでもアンカーが安定します。従来の画像引数順序
`file,xoffset,yoffset[,angle]` は変更されていません。

`\imgscale(sx[,sy])` はテクスチャサンプル座標をラップ前に除算します：`2` は
テクスチャを 2 倍に拡大、`0.5` は 2 倍に縮小します。`sy` を省略すると両軸に
`sx` が使われます。負の値は絶対値を取り、ゼロまたは無効な入力は 1:1 に戻り、
値は [1/256,256] にクランプされます。`\imgscale0` はコンパクトなリセット形で、
`\t` アニメーションに対応します。

画像の保存とサンプリングは、出力ピクセルを変えずに最適化されています：
デコードされた PNG 行は単一の連続メモリを共有し、テクスチャ座標はオーバーレイの
行/列ごとにキャッシュされ、整数座標または単軸補間は数学的に等価な高速パスを
使います。

### `\shadblur(radius)` / `\bordblur(radius)` — レイヤー別ブラー

単一レイヤーのみに作用するガウシアンブラー：シャドウ/アウトラインパスは、その
レイヤー半径を基本 `\blur` に加算してオーバーレイを再ラスタライズします。
本文はシャープなままシャドウが拡散、あるいはアウトラインが柔らかくフィルは
明瞭のままにできます。コンパクト記法 `\shadblur4`、`\t` アニメーション対応、
ゼロ値で無効。

### `\mgrad(c1,c2[,c3,...])` — マルチストップグラデーション

2〜8 個の ASS 16 進カラーストップを現在のグラデーション方向に沿って等間隔に
配置：`\vgrad` 角度または `\rgrad` 放射が設定済みならその方向に沿い、
未設定なら水平です。区分的線形補間で、本文チャンネルに作用します。
`\mgrad0` で無効。

### `\pin(x1,y1,x2,y2,x3,y3,x4,y4)` — コーナーピン透視

行を任意の 4 点四角形へはめ込む射影（ホモグラフィー）ワープ：行レイアウト
ボックスの 4 隅が左上から時計回りに、指定した 4 つの出力ピクセル角点へ
マッピングされます。テキストを傾いた看板、スクリーン、ブックカバーに、真の
遠近短縮で貼り付けられます。ワープは他のすべての変換の上に適用されます
（回転、円弧、波はその下で合成）。`\pin0` で無効。`\t` は 8 つの座標すべてを
アニメーションします。従来の `\distort`（3 点双線形、ボックス相対）とは異なり、
`\pin` は絶対出力ピクセルでの真の透視です。

### RGB 色収差分離（\rgb）

\rgb タグは文字の赤と青のチャンネルを逆方向にずらし、色収差/グリッチ効果を
生みます。次の 2 つの書き方は等価です：

```ass
{\rgb4}テキスト
{\rgb(4)}テキスト
```

距離は出力ピクセル単位で、負の値でエッジ色の方向を入れ替えられます。
\t アニメーションに対応し、上限は 4096、\rgb0 で無効。効果は文全体に作用し、
各ワードの値が異なる場合は絶対値最大のものが使われます。

### テキストグロー（\glow）

\glow は文字の後ろに柔らかいハローを描きます。次の 2 つの書き方は等価です：

```ass
{\glow20}テキスト
{\glow(20)}テキスト
```

2 番目の値は線形強度倍率です（デフォルト `1`）：

```ass
{\glow(20,1.5)}より強いグロー
{\glow0}グロー無効
```

半径は出力フレームのピクセルで測ります（\blur と同じ）。グローはデフォルトで
文字本体の色を使います。グラデーションと画像フィルは自身のフィル色を保ち、
アウトラインはグロー形状のみを提供し、シャドウはグローに参加しません。
文字の透明度、\fade/\fad、矩形/ベクター/移動 \clip/\iclip、\t アニメーションは
すべて正しくグローに影響します。半径の上限は 4096 出力ピクセル、強度倍率の
上限は 64 です。

グローはブルーム式マルチスケールアルゴリズムを使います：発光形状を 3 つの半径
（密な明るい核、中間、広く柔らかい外側ハロー）でガウス近似ブラーし、16bit
リニアライトパイプラインで加算蓄積してから Reinhard トーンカーブで圧縮するため、
ハローは白く飽和した塊ではなく滑らかな輝度グラデーションを保ちます。強度倍率は
露出に相当し、トーンマッピング前に線形光量をスケールします。これは依然として
alpha 混合のラスタエフェクトであり、After Effects Deep Glow の真の HDR 加算の
複製ではありません。

### すべてのマシンで同じフォントを使う

スクリプトが指定したフォントがインストールされていなければ、プラットフォームが
自動で置き換えます——Windows、macOS、Linux でそれぞれ異なるフォントに。
3 つの回避方法があります：

- **フォントをスクリプトに埋め込む**（`[Fonts]`。例：Aegisub の「アタッチメント」機能）。
- **フォントフォルダを共有する。** 中のフォントは埋め込みフォントと同じく検索対象で、
  インストール済みフォントより優先されます。vsfmrender では `--fontdir DIR`、
  Aegisub と AviSynth では環境変数 `VSFM_FONT_DIRS`
  （複数フォルダは Windows では `;`、その他では `:` で区切り）。
- **確認する。** vsfmrender はレンダリング後に置き換えられたフォントをすべて
  一覧表示します。`--strict-fonts` を付けるとエラー扱いになります。
  Aegisub と AviSynth では `VSFM_FONT_LOG=1` を設定すると、各フォントの解決時に
  結果が出力されます。

## オリジナルとの一致度

Windows 上でオリジナル VSFilterMod の CSRI プラグインと比較し、両側のグリフ
カバレッジ領域の一致率（IoU）をイベントごとに計算しています。1.000 は
ピクセル完全一致を意味します。

| テストスクリプト | カバー内容 | IoU |
| --- | --- | --- |
| `tests/smoke.ass` | 基本スタイルと配置 | 1.000 |
| `tests/frs.ass` | 各角度の `\frs`。CJK 文字、`\fsp`、ボールド、イタリック、改行 | 0.977–0.999 |
| `tests/vertical.ass` | `@` 縦書きフォント。句読点、拼音、ギリシャ文字、全角文字 | 0.967–1.000 |
| `tests/fallback.ass` | ラテンフォント内の CJK・ハングル文字（グリフフォールバック） | 0.985–0.999 |
| `tests/bold.ass` | 合成ボールド。イタリック、`\frs`、フォールバックを含む | 0.977–1.000 |

イベントタイミングはすべて `MaskSubMod` のクロック（単精度丸めを含む）で
計算されるため、BDN+XML の各イベントの開始・終了フレームはオリジナルと
同一です。残る差異はグリフエッジのアンチエイリアスで、1 ピクセル以内です。

**プラットフォーム間の出力は「近い」ではなく完全に同一です。** フォント
ファイルが同じなら、Windows、Linux、macOS、x86-64 と ARM のすべてのビルドが
同じピクセルを出力します：レンダリングに SIMD、CPU、コンパイラに依存する
コードパスはありません。CI は全プラットフォームで `tests/consistency/` を
レンダリングし、共通の `expected.txt` と異なるピクセルがあれば失敗します。
マシン間でまだ異なり得るのは、どのフォントがインストールされているかだけです
（「既知の問題」参照）。

## オリジナルとの違い

**グリフは GDI ではなく FreeType 由来。** 組版コードが GDI に依存する部分は、
エンジンがすべてエミュレートしています：`LOGFONT` の正の高さは em サイズではなく
セル高（これこそ他のレンダラーで VSFilter 字幕のフォントサイズが間違う典型的な
原因）。`\frs` では GDI がフォントメトリクスを変え、非公開の規則でグリフを
配置・回転・計測します。`@` フォントは CJK グリフを横倒しにし、GSUB `vert`
縦書きグリフへ切り替えます。これらはすべて再現済みです（詳細は
`src/font/font_engine.cpp`）。名前によるフォント検索は引き続き各プラットフォーム
ネイティブの API を使います：DirectWrite、CoreText、fontconfig。

**グリフフォールバックは GDI と一致。** スタイルフォントに欠けた文字は、
そのフォントの Windows SystemLink リスト、宋体と Malgun Gothic、macOS と
Linux の CJK フォント、プラットフォーム自身のフォールバック機構の順で取得します。
フォールバックグリフのサイズ、ベースライン、GDI がこうした文字に施す字間調整は
すべて GDI と同一です。

**合成ボールドは GDI の規則で実装**されており、回転した文字で太い筆画を含め、
ポイントごとに計測されています。

**埋め込みフォントが使えます**。CSRI 経由でも全プラットフォームで：
アタッチメントフォントは FreeType に直接渡され、システムにインストールされません。
GDI がフォントを見つけられる名前なら、こちらでも見つけられます：Windows
ファミリ名（例 "Source Han Sans SC Medium"）、タイポグラフィファミリ名、フル名、
あらゆる言語のローカライズ名（旧式 CJK フォントの GBK/Big5/Shift-JIS エンコード名を
含む）。同一ファミリに複数ウェイトが埋め込まれている場合は、GDI と同じく要求された
ウェイトとイタリックに応じたフォントファイルが選ばれます。埋め込み可変フォントの
名前付きインスタンスも GDI の方式で列挙されます（例 "Family Black"）。通常の
フォールバックフォントにもない文字は、プラットフォーム自身のフォールバックの前に
埋め込みフォント（と `--fontdir` フォルダ）を先に検索するため、どのマシンでも
結果が同じになります。

**DirectShow 部分を削除。** DirectShow フィルタとそのプロパティページ、
VobSub/DVB/HDMV/CC/USF/SSF/RealText パーサー、DirectX 字幕レイヤーバックエンドは
削除されました。Aegisub、AviSynth、BDN+XML 出力のいずれにも不要です。AviSynth と
VapourSynth の `VobSub()` はいずれも移植されていません。

**VapourSynth プラグインは API 4 ベース**（オリジナルは廃止済み API 3）で、
高ビット深度はフル精度で混合され、サンプルを半分に分割しません。

**レンダリング結果はマシンに依存しません。** DPI は 96 に固定、文字セットから
コードページへのマッピングは固定テーブルを使います。唯一の例外は Windows での
グリフフォールバックで、GDI と同じくそのマシンの SystemLink 設定に従います。

## 既知の問題

- OpenType-CFF 形式の `@` 縦書きフォント（例 `@Source Han Sans`）は、こちらでは
  そのフォントでレンダリングされます。オリジナルの GDI は CFF フォントを縦書きで
  開けず、暗黙にシステムフォントへ切り替えます（中国語版 Windows では宋体）。
  これをそのまま真似ると出力が Windows の言語設定に依存してしまいます。
- `@MS Gothic` と `@Malgun Gothic` はギリシャ文字とキリル文字を回転しませんが、
  本移植では横倒しにします。また宋体と黒体は `\frs` での仮名スペーシングが他の
  フォントと異なります。この 2 点は再現不可能な GDI 内部テーブルによるものです。
- `@Arial` のような GDI が認識しないフォント名は、GDI に行全体（ラテン文字を
  含む）を宋体へ切り替えさせます。こちらではラテン文字はスタイルフォントのままです。
- Linux と macOS のビルドは Windows ビルドとピクセル単位で一致します（CI で検証）。
  ただしスクリプトが指定したフォントがインストールされていなければ、各
  プラットフォームがそれぞれ異なるフォントに置き換えます。フォントを
  スクリプトに埋め込めば（`[Fonts]`）回避できます。
